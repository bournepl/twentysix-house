# House Catalog Roadmap

แผนพัฒนาส่วน **แบบบ้านของเรา** สำหรับแยกแบบบ้านมาตรฐานออกจากผลงานออกแบบและผลงานก่อสร้างจริง

## เป้าหมาย

- สร้างพื้นที่ให้ลูกค้าเลือกชมแบบบ้านที่สามารถนำไปปรับให้เหมาะกับที่ดิน งบประมาณ และการใช้ชีวิตได้
- แยกความหมายของ "แบบบ้านของเรา" ออกจาก "ผลงานของเรา" ให้ชัดเจน
- เชื่อมการ์ด House Catalog บนหน้า Home ไปยังข้อมูลที่ใช้งานได้จริง
- รองรับการเพิ่มแบบบ้านในอนาคตโดยไม่ต้องแก้โครงสร้างหน้าใหม่

## โครงสร้างหน้าและ URL

| หน้า | ชื่อภาษาไทย | URL |
| --- | --- | --- |
| หน้ารวม | แบบบ้านของเรา | `/house-catalog` |
| หน้ารายละเอียด | รายละเอียดแบบบ้าน | `/house-catalog/:slug` |

คำที่ใช้ในหน้าเว็บ:

- เมนูหลัก: **แบบบ้านของเรา**
- ปุ่มจากหน้า Home: **ดูแบบบ้านทั้งหมด**
- ปุ่มบนการ์ด: **ดูรายละเอียดแบบบ้าน**
- CTA ในหน้ารายละเอียด: **ปรึกษาเพื่อปรับแบบ**

### งานที่ต้องทำ

- ยืนยันว่าแบบบ้านแต่ละรายการเป็นแบบมาตรฐานที่บริษัทพร้อมนำเสนอจริง
- ยืนยันชื่อบ้านใน Pure Collection ได้แก่ Yu Yen, Yu Plearn, Yu Sabai และ Yu Sook
- คัดเลือกรูปปก รูปด้านต่าง ๆ แปลน และรูปภายในของแต่ละแบบ
- รวบรวมข้อมูลพื้นที่ใช้สอย ห้องนอน ห้องน้ำ ที่จอดรถ จำนวนชั้น และช่วงงบประมาณ
- ระบุว่าข้อมูลใดเผยแพร่ได้ และข้อมูลใดต้องใช้คำว่า "เริ่มต้น" หรือ "โดยประมาณ"

### ผลลัพธ์

- รายการแบบบ้านที่พร้อมเผยแพร่ชุดแรก
- โฟลเดอร์รูปของแต่ละแบบที่ตั้งชื่อเป็นระบบ
- ข้อมูลจริงที่ผ่านการตรวจสอบจากทีม

### เกณฑ์จบเฟส

- แบบบ้านทุกหลังมีรูปปกและข้อมูลหลักครบ
- ไม่มีตัวเลขสมมติในข้อมูลที่จะเผยแพร่

## Phase 1: ออกแบบโครงสร้างข้อมูลกลาง

**สถานะ:** เสร็จแล้ว

### งานที่ต้องทำ

- [x] สร้าง interface `HouseCatalogItem`
- [x] สร้างไฟล์ข้อมูลกลาง `src/app/house-catalog/house-catalog.data.ts`
- [x] กำหนด `slug` ที่อ่านง่ายและไม่ซ้ำกัน
- [x] แยก `coverImage`, `cardImage` และ gallery เพื่อควบคุมการใช้รูป
- [x] เตรียม field สำหรับการกรอง ราคา และ SEO ในอนาคต
- [x] เปลี่ยน House Catalog บนหน้า Home ให้ใช้ข้อมูลกลางแทนข้อมูลชั่วคราว

### โครงสร้างข้อมูลที่แนะนำ

```ts
export interface HouseCatalogItem {
  slug: string;
  name: string;
  thaiName: string;
  collection: string;
  style: string;
  description: string;
  concept: string;
  coverImage: string;
  cardImage: string;
  gallery: string[];
  floorPlanImages: string[];
  floors?: number;
  usableArea?: number;
  bedrooms: number;
  bathrooms: number;
  livingRooms: number;
  kitchens: number;
  parking: number;
  landWidth?: number;
  landDepth?: number;
  startingBudget: number;
  priceDisclaimer: string;
  tags: string[];
  featured: boolean;
}
```

### ผลลัพธ์

- ข้อมูลหน้า Home หน้ารวม และหน้ารายละเอียดใช้แหล่งข้อมูลเดียวกัน
- เพิ่มหรือลบแบบบ้านได้โดยแก้เฉพาะไฟล์ข้อมูล

### เกณฑ์จบเฟส

- ไม่มีข้อมูลแบบบ้านซ้ำอยู่หลาย component
- ทุก `slug` เปิดหาแบบบ้านที่ถูกต้องได้

### เกณฑ์จบเฟส

### ผลการดำเนินงาน

- เพิ่มคำสั่ง `npm run images:house-catalog` เพื่อสร้างภาพด้วย Sharp แบบทำซ้ำได้

- ย้ายภาพต้นฉบับ 54 ไฟล์ไป `source-media/house-catalog/pure-collection` เพื่อไม่ให้ Angular copy เข้า production build
- ชุดภาพที่ deploy ลดจาก 11.78 MB เหลือ 3.54 MB โดย gallery ใช้ `contain` เพื่อรักษารายละเอียดของภาพต้นฉบับ
- production build ผ่านและ prerender สำเร็จ 15 routes พร้อมตรวจว่าไม่มีพาธภาพ Pure Collection เดิมหลงอยู่ใน HTML หรือ `dist`

## ลำดับการพัฒนาแบบ MVP

หากต้องการเปิดใช้งานเร็ว ให้เริ่มด้วยลำดับนี้:

1. Phase 0: ยืนยันข้อมูลแบบบ้าน 4 แบบแรก
2. Phase 1: สร้างข้อมูลกลาง
3. Phase 2: สร้างหน้ารวม
4. Phase 3: สร้างหน้ารายละเอียด
5. Phase 4: เชื่อม Home เมนู และ Footer
6. Phase 5: ทำ metadata และ prerender ขั้นพื้นฐาน
7. Phase 6-7: ปรับ performance และตรวจรับก่อน deploy

ฟังก์ชันตัวกรองขั้นสูง การเปรียบเทียบแบบบ้าน รายการโปรด และระบบหลังบ้าน สามารถเก็บไว้เป็นเฟสต่อยอดหลัง MVP ได้

## ขอบเขตที่ไม่ควรรวมกับ House Catalog

- บ้านที่ก่อสร้างและส่งมอบจริง ให้อยู่ใน `/ourworks/completed`
- ผลงานออกแบบเฉพาะลูกค้า ให้อยู่ใน `/ourworks/design`
- บทความความรู้เรื่องบ้าน ให้อยู่ใน `/blogs`

การแยกทั้งสามส่วนจะช่วยให้ลูกค้าเข้าใจว่าแบบใดเป็นแบบที่เลือกไปปรับได้ แบบใดเป็นผลงานออกแบบ และแบบใดสร้างเสร็จจริงแล้ว
